# Per-move unlock gate evaluated directly on $ACTOR$, NOT via
# can_execute_decision: decisions carry implicit taker requirements
# (ruler status among them) that unlanded combatants fail wholesale,
# emptying their AI loadouts and making them pass every turn. This
# trigger is the unlock authority for BOTH the loadout editor and
# runtime combat; the hidden decisions only carry the same lines as
# failure-description material.
# Two-level dispatch: a coarse switch on the move's config_section
# (power family) selects a per-section sub-switch on skill_key. CK3
# switch is first-match, so grouping shrinks the per-call scan from the
# whole gated-move list to one section's gated moves. Ungated moves,
# sections with no gated moves, and hand-registered manual moves fall
# through a (sub-)fallback = always yes. config_section is stored on the
# move story by POD_init_combat_move (flag:<config_slug>); the coarse
# cases reuse config_section_slug so they match the stored var exactly.
#   $STORY$ = the POD_combat_move story_cycle
#   $ACTOR$ = character whose unlock (trait/perk) is tested
